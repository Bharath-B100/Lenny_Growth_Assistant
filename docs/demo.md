# Camera-on demo — 2–3 minutes

## Prepare

Use Local Ollama, warm the model, and prepare real completed QA, essay, Markdown,
and HTML conversations before recording: laptop generation can take minutes. Clearly
say when switching to a pre-generated example; do not portray it as instant inference.
Use only outputs you have checked against their excerpts; consult verification.md
for current successful runs and failures. Free-tier quota can block subsequent
requests; show genuine saved outputs and explain the limit. Keep keys,
private settings, unrelated chats, and account details off screen. Record screen plus
your actual camera; this project does not fabricate camera footage.

## Speaking script

- **0:00–0:20:** “This is my Lenny Growth Assistant. It searches podcast transcripts
  to help product teams get source-backed answers and create useful writing.” Show library.
- **0:20–0:55:** Show a completed Local Ollama QA and a follow-up. Open a citation and
  compare its excerpt to the answer. Show another chat and saved conversation history.
  Briefly save an insight or open Discover; do not display invented match percentages.
- **0:55–1:30:** Show a completed Ship30 essay, word count, hook, headings and takeaway.
  Mention the dedicated checked-in writing skill and evidence-based generation.
  Show the target-audience field and actual word count, not the reference demo's 741-word example.
- **1:30–2:00:** Open Markdown and HTML artifacts beside chat. Show Preview, Source,
  Copy/Download. Explain scripts/external resources are blocked.
- **2:00–2:25:** Show the provider selector and real cloud output if authentication is
  resolved. Explain no silent cloud fallback and how local generation protects privacy.
- **2:25–2:50:** Briefly show FastAPI + Pi + PostgreSQL architecture, one-command start,
  and an honest limitation: slow laptop inference and lexical retrieval quality.
  The frontend is vanilla JavaScript and the local model is Qwen3 4B Instruct;
  do not describe this build as React/Chroma/Llama 3.2.
